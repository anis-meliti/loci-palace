# Memory vault

This repository is persistent memory for its owner. Read it before answering questions about them, their projects, or past decisions.

## How to find things — read the manifest, don't search

`{{VAULT_DIR}}/Views/manifest.tsv` is a generated index of every note: one tab-separated line with `source · path · type · status · updated · title · covers`.

**Routing procedure:**

1. Read `{{VAULT_DIR}}/Context/CRITICAL_FACTS.md` — identity, ~150 tokens, always worth it.
2. For anything else, read the manifest and scan the `covers` column for terms matching the question.
3. Open the note at the matching `path`. Just that one.
4. Only if no line matches, fall back to searching — and say so, because a miss means that note's `covers` needs curating.

Searching to find a file costs more every time the vault grows and surfaces stale notes alongside current ones. A bounded index does not. The manifest is regenerated by `{{VAULT_DIR}}/System/manifest.py` and a pre-commit hook fails if it is stale, so it can be trusted as current.

Do not read the vault for general questions unrelated to the owner or their projects.

## Before writing anything

Read `{{VAULT_DIR}}/System/Schema.md`. It is binding.

Non-negotiables:

- Every note needs `type`, `status`, `updated`, `tags` as the **first bytes of the file** — never inside a code fence
- `{{VAULT_DIR}}/Context/`, `{{VAULT_DIR}}/Index.md`, `{{VAULT_DIR}}/System/`: full overwrite only, never append
- Rewrite only inside `<!-- @generated:name -->` blocks; unmarked content belongs to the owner
- Bump `updated:` on content writes — but never for routing-metadata-only edits
- Never hand-write a status that `Views/Projects.base` already derives
- Never hardcode an absolute path or the vault directory name
- Prefer surgical edits to full rewrites

After adding or renaming a note:

```
python3 {{VAULT_DIR}}/System/manifest.py
```

## Validation

```
python3 {{VAULT_DIR}}/System/lint.py             # schema, duplication, dead links, orphans
python3 {{VAULT_DIR}}/System/manifest.py --check  # manifest freshness
```

Both run automatically via the pre-commit hook. A commit failing either is blocked.

## Session end

Follow the distillation protocol in `{{VAULT_DIR}}/Index.md`: write a session note, update affected project notes, log settled choices in `{{VAULT_DIR}}/Context/Decisions.md`, regenerate the manifest.

## Machinery vs content

`{{VAULT_DIR}}/System/`, `{{VAULT_DIR}}/Views/` structure, `{{VAULT_DIR}}/Index.md`, and this file are **machinery** — portable to other machines, and must contain no personal content.

`{{VAULT_DIR}}/Context/`, `{{VAULT_DIR}}/Projects/`, `{{VAULT_DIR}}/Sessions/`, `{{VAULT_DIR}}/Archive/`, and `Views/manifest.tsv` are **content** — they never leave this machine.

When editing machinery, use generic language: no personal names, employer names, or specific project titles.

## Environment
